F2FS garbage collection with device copy offload
Flow for one victim segment: valid blocks are moved by the UFS device instead of being read and rewritten by the CPU.
BEFORE: ONE BLOCK AT A TIME
Allocate 1 block Copy command for 1 block → Update file pointer
Ċ repeated for every valid block → many small commands
NOW: BATCHED PER VICTIM SEGMENT
1 Collect
Scan the victim segment and
keep only the valid blocks:
source block address, owning
file and offset. Wait until each
source block is fully written to
flash. Up to 128 blocks per
batch (configurable).
2 Allocate
For each collected block, take
the next free block in the cold-
data log. Destinations come
out consecutive, so they can
be copied as ranges.
3 Copy
Merge consecutive blocks into
ranges and send a few device
copy commands (source
ranges → destination ranges).
Each command completes
before moving on.
4 Commit
ALSO REQUIRED
Point each file block to its new
address, mark the old block
invalid, drop caches of the old
copy and release the locks.
A If a copy fails
Undo the allocation for those
blocks and move them with the
normal CPU copy path.
Nothing is lost.
Safety: the per-file GC locks are held from step 1 to the end, and the checkpoint lock during steps 2 to 4, so no file update or checkpoint can change these
blocks halfway. Node blocks are not offloaded and keep using the normal path.
