F2FS: Introduce batch-based GC migration using copy-offload
F2FS / Block Layer / UFS
Optimization / New Feature
Yes
Major
Currently, F2FS garbage collection migrates valid blocks individually, issuing separate 4 KB copy-offload requests. This introduces repeated request submission and completion overhead. When multiple valid blocks are physically contiguous, processing them individually prevents efficient utilization of the device's copy-offload capability.
Introduces contiguous-block detection during GC migration. Groups eligible blocks with contiguous source and destination physical addresses into larger copy-offload requests. Retains existing F2FS destination allocation and metadata-update mechanisms. Uses the existing block-by-block migration path when batching is not possible or copy-offload fails.
Reduces the number of UFS copy-offload commands by combining multiple eligible 4 KB transfers into larger requests. Potentially reduces command submission overhead and GC execution time. Improves utilization of UFS device-copy capabilities. Actual performance gains depend on block contiguity, device copy limits, and batching efficiency.
