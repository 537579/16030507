Patch Title
F2FS: Add test suite to validate GC copy-offload functionality

Problem Statement
F2FS garbage collection migrates valid data blocks from victim segments to new locations using conventional read-and-write operations. This can increase CPU utilization, memory traffic, and UFS I/O overhead. A test framework is required to validate whether copy-offload is triggered during GC and to compare GC behaviour with copy-offload enabled and disabled.
Solution
Introduces an automated F2FS GC test suite with foreground and background GC workloads. Supports enabling/disabling copy-offload through a sysfs control node. Adds copy-offload call counters and GC statistics to track GC activity, migrated blocks, and offload invocation counts. Includes workloads such as sequential writes, random overwrites, fsync pressure, parallel writers, idle GC, urgent GC, and ENOSPC recovery. Provides automated execution and result comparison between both configurations.
Impact on UFS / F2FS
Enables systematic validation of copy-offload integration during F2FS garbage collection. Helps identify workloads where offload is actually triggered and distinguishes conventional GC migration from offloaded data copying. Provides visibility into GC activity and copy-offload invocation frequency. Establishes a test baseline for evaluating potential reductions in CPU overhead, host-side data movement, and UFS command traffic.
